# 실버잡 데이터 분석·예측 파이프라인

매일 노인 일자리 공고를 수집해 **이력을 쌓고**, 홈페이지가 바로 읽을 수 있는 **분석 뷰**와 **주간 신규 공고 예측**을 Supabase에 만들어 둡니다.

```
공공 API ──(매일 06:07 KST, GitHub Actions)──▶ ingest_postings()  ──▶ job_postings / job_snapshots / job_daily_stats
                                                                     │
                                      pipeline/forecast.py ◀─────────┘──▶ job_forecasts
                                                                     │
홈페이지(anon 키, 읽기 전용) ◀── v_daily_flow · v_weekly_trend · v_opportunity_index · v_time_to_close · v_condition_mix · v_latest_forecast
```

## 수집 출처

| `source` | API | 내용 | 수집 방식 |
|---|---|---|---|
| `kordi` | 한국노인인력개발원 노인 구인정보 (`SenuriService`) | 워크넷 등 민간 노인 구인공고 | 최신순 목록에서 접수 중인 공고만, 빈 지역은 상세조회로 보완 |
| `kordi_jobbsn` | 한국노인인력개발원 자립형일자리 사업모집공고 (`JobBsnInfoService`) | 정부 노인일자리 사업(시장형·인턴십 등) 참여자 모집 | 해당 연도 목록 전체(1,000건씩)에서 `모집중`만 |
| `work24` | 고용24(워크넷) 채용정보 (`callOpenApiSvcInfo210L01`) | 민간 공고 중 **(준)고령자 우대**(`pfPreferential=8`) | 조건에 맞는 공고 전체(시간 제한 없음). 사이트와 같은 제외 필터 사용 |

- **고용24:** silverjob.kr의 Netlify 함수(`sync-work24-jobs.mjs`)는 15초 안에 받은 만큼만 저장해서, 리포트 총계가 날마다 흔들렸습니다(일자리가 줄어든 게 아니라 덜 받은 것). 이 파이프라인은 전체를 받고, 고용24가 알려준 전체 건수의 95%에 못 미치면 그날 반영하지 않습니다.
  - (준)고령자 우대 공고는 전국 약 5만 8천 건(2026년 10월)이라 하루 약 580번 호출합니다(20개씩 동시, 2~3분). 사이트 기준 직종 필터로 걸러 저장합니다.
  - 직종은 고용24 공식 직종코드(`jobsCd`)로 '사회공헌'을 실제 일(요양·간병, 간호·치료, 돌봄·복지)로 나눕니다.
  - 급여는 시급·일급·월급·연봉으로 정규화합니다(`wage_amount`, `wage_unit`).
- **두 출처의 중복:** 노인 구인정보에는 워크넷 공고가 일부 섞여 있습니다(같은 구인인증번호). 고용24를 먼저 받고, 노인 구인정보에서는 이미 진행 중인 고용24 공고를 뺍니다.
- **급감 방지:** 어느 출처든 전날의 절반 아래로 줄면 일부만 받은 것으로 보고 반영하지 않습니다.

- 자립형일자리는 시도·시군구가 항상 들어 있고, 모집인원(`raw.hpInvtCnt`)도 함께 보존합니다.
- 연말에 다음 해 사업 참여자를 대량으로 미리 모집하는 등 민간 구인과 흐름이 달라서, 주간 예측은 지금은 `kordi`만 대상으로 합니다(`FORECAST_SOURCES`).
- 두 API는 같은 공공데이터포털 인증키를 씁니다.

## 홈페이지 (`site/index.html`)

어르신용 한 페이지 화면입니다. 큰 글씨와 높은 대비를 쓰고, 다크 모드와 휴대폰 화면을 지원합니다.
Supabase 공개(publishable) 키로 공개 뷰만 읽습니다.

화면 순서는 어르신이 가장 먼저 찾는 것부터입니다.

1. **머리띠:** 지역 선택, "OO에는 지금 N개의 일자리가 어르신을 기다리고 있어요" 한 문장, 일자리 날씨(지난주 새 공고 대비 최근 4주 평균: 맑음, 구름 조금, 흐림)
2. **요약 카드:** 지난주 새 공고(그 전 주 대비 ▲▼), 이번 주 또는 다음 주 예상 범위, 정부 노인일자리 사업 모집인원
3. **지금 지원할 수 있는 일자리:** 서둘러 지원할 공고(D-day)와 새로 올라온 공고. 정부 사업과 민간 공고를 색으로 구분합니다.
4. **어떤 일이 많을까요?:** 직종별 막대(아이콘 포함)
5. **공고가 늘고 있을까요?:** 최근 12주 막대와 예상(빗금), 표 보기
6. **이 숫자는 어떻게 계산했나요?:** 접어 둔 설명

**현황 리포트 (`site/report.html`):** 지역을 고르면 모집 중 공고, 민간/정부 사업, 어르신 1만 명당 공고, 다음 주 예상, 직종별 공고 수와 대표 급여(`v_category_pay`), 어르신 1만 명당 공고로 본 지역 순위(`v_opportunity_index`), 주간 추세, 마감 속도(`v_time_to_close`, 마감 기록이 30건 이상 쌓이면 표시)를 보여줍니다. silverjob.kr의 `/report.html`에 `data-page="report"`로 끼워 넣습니다.

기존 홈페이지에 끼워 넣는 방법은 [docs/EMBED.md](docs/EMBED.md)에 있습니다. 코드 두 줄로 넣고, 높이는 자동으로 맞춰지며, 대표색·바탕색·지역 고정을 설정할 수 있습니다.

배포는 `pages.yml`이 맡습니다. 처음 한 번 Settings → Pages → Source를 **GitHub Actions**로 바꿔야 합니다.

## 홈페이지에서 쓰는 뷰

| 뷰 | 보여주는 것 | 화면 문구 예시 |
|---|---|---|
| `v_daily_flow` | 날짜·시도·직종별 신규 / 마감 / 진행 중 공고 수 | "오늘 서울에 새 일자리 5개가 올라왔어요" |
| `v_weekly_trend` | 주간 신규 공고 수, 지난주·최근 4주 평균과의 차이 | "이번 주 23개, 지난주보다 10개 늘었어요" |
| `v_opportunity_index` | 고령 인구 1만 명당 진행 중 공고 수, 전국 평균 대비 배율 | "우리 지역은 전국 평균보다 1.3배 많아요" |
| `v_time_to_close` | 직종별 공고가 마감되기까지 걸리는 기간(중앙값), 7일 안 마감 비율 | "경비·청소는 보통 3일 안에 마감돼요. 서두르세요!" |
| `v_condition_mix` | 직종 × 주당 근무시간 구간별 공고 수, 시급 환산 중앙값 | "주 15시간 이하 일자리가 가장 많아요" |
| `v_latest_forecast` | 시도별 앞으로 4주간 신규 공고 예상치와 80% 범위 | "다음 주 경기도 새 일자리 19~43개 예상" |

## 예측 방법 (`pipeline/forecast.py`)

1. 시도별(+전국) 주간 신규 공고 수 시계열을 만듭니다. 출처가 게시일을 주면 게시일 기준이라 수집 전 기간도 반영됩니다.
2. 후보 모델: **직전 주 값(기준선)**, **최근 4주 평균**, **작년 같은 주**(52주 이상 쌓이면), **감쇠 추세 지수평활**.
3. 과거 각 시점에서 그때까지의 데이터만으로 1~4주 앞을 예측해 실제와 비교합니다(롤링 백테스트). 오차가 가장 작은 모델을 고릅니다.
4. 예측 범위는 백테스트 오차의 10~90% 분위로 만듭니다(80% 범위).
5. **기준선보다 정확하고(`backtest_rel_mae < 1`) 16주 이상 쌓였을 때만** `publishable=true`가 되어 홈페이지에 노출됩니다.

데이터가 1년 이상 쌓이면 직종별 예측이나 LightGBM 같은 전역 모델로 확장할 수 있습니다. 확장해도 같은 백테스트 기준을 통과해야 노출됩니다.

## 데이터 안전장치

- **빈 수집 거부:** 0건이 오면 반영하지 않습니다. 출처 장애를 "전부 마감"으로 오해하지 않기 위해서입니다.
- **출처별 마감 처리:** 한 출처의 수집이 다른 출처의 공고를 마감시키지 않습니다.
- **재게시 처리:** 마감됐다 다시 올라온 공고는 마감이 해제되고, 신규로 세지 않습니다.
- **첫 수집일 처리:** 첫 수집일에는 기존 공고를 신규로 세지 않습니다.
- **권한:** 쓰기는 서비스 롤 키(배치)만, 홈페이지 anon 키는 읽기만 합니다.

## 설정

1. Supabase에 `supabase/migrations/20261026000000_silverjob_analytics.sql`을 적용합니다.
2. 공공데이터포털에서 [한국노인인력개발원 노인 구인정보](https://www.data.go.kr/data/15015153/openapi.do)와 **한국노인인력개발원_자립형일자리 사업모집공고** API를 활용신청하고 인증키를 받습니다.
   - `from_senuri`가 `SenuriService/getJobList`(XML, 시작접수일 최신순)에서 접수 중인 공고 전체를 받습니다(하루 약 300건, 7페이지 안팎).
   - **직종:** API 직종 필드(`jobclsNm`)는 대부분 비어 있어서 제목 키워드로 분류합니다. 청소·미화, 경비·보안, 조리·급식, 돌봄·복지 등 10개 직종으로 나눕니다(`CATEGORY_KEYWORDS`).
   - **지역:** 근무지(`workPlcNm`)가 비어 있는 공고는 상세조회(`getJobInfo`)의 사업장 주소로 보완합니다. 실측으로 지역 미상이 55%에서 4%로 줄었습니다. 상세조회는 건당 수 초가 걸려서 새 공고만 조회합니다.
   - 광주·전남은 API 표기에 맞춰 `전남광주` 하나로 묶습니다.
   - 처음 한 번 `python -m pipeline.backfill --since 2024-10-01`을 실행하면 과거 공고로 주간 추세를 채워, 첫날부터 예측을 쓸 수 있습니다. 자립형일자리는 `--source kordi_jobbsn`을 붙입니다. Actions의 **backfill-history**에서도 실행할 수 있습니다.
3. GitHub 저장소 Secrets에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `DATA_GO_KR_SERVICE_KEY`, `WORK24_API_KEY`(고용24 인증키, silverjob.kr Netlify 환경변수와 같은 값)를 등록합니다. `WORK24_API_KEY`가 없으면 고용24 수집은 건너뜁니다.
   - 인증키는 인코딩된 키와 원본 키 중 어느 것을 넣어도 됩니다.
   - 인증키 오류나 호출 한도 초과가 나면 그날 수집은 반영하지 않습니다. 반영하면 공고가 일괄 마감으로 기록되기 때문입니다.
4. 시도별 65세 이상 인구를 `region_population`에 적재합니다(`supabase/seed/region_population_2026_08.sql`, 행정안전부 주민등록 인구통계 2026년 8월 말, 16개 시도 합계 11,278,011명 = 전국 합계와 일치). 이 데이터로 기회 지수(고령 인구 1만 명당 공고 수)를 계산합니다. 새 수치는 `year`를 올려 넣으면 뷰가 최근 연도를 씁니다.

수동 적재는 `python -m pipeline.ingest --source manual --csv 파일.csv`로 할 수 있습니다. CSV 헤더는 정규화 필드명을 씁니다.
