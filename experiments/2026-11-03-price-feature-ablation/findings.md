# 가격 피처 ablation 테스트 — 결과 보고

- 목적: `market_price_features.py`(KAMIS 가격 피처)를 `model_selector.py`
  파이프라인에 넣었을 때 실제로 WAPE가 개선되는지 확인.
- **중요한 제한**: 샌드박스가 apis.data.go.kr에 접속할 수 없어 실제 KAMIS
  가격 데이터를 쓸 수 없었다. 더 근본적으로는 "실제 원재료 가격이 성오테크
  고객사의 실제 수요를 예측하는가"는 실제 고객 파일럿 데이터 없이는 검증
  불가능한 사업 가설이다. 이 테스트가 확인하는 것은 좁다 — **가격-수요
  인과관계가 데이터에 존재할 때, 기존 파이프라인이 그 신호를 포착해 WAPE를
  개선할 수 있는 구조(배관)가 맞는지** 여부다. 합성(synthetic) 데이터로
  진행했다.

## 실험 설계

- 730일 합성 수요: 요일 계절성(주말 +15) + 가격 변화율(7일) 반영, 탄력성
  0.5(가격 10% 상승 시 수요 약 5% 감소), **실제 효과는 3일 지연**(발주
  반영 시차 가정 — 지연을 모른다는 현실적 설정)되도록 함.
- 합성 가격: 평균회귀 + 약 40일에 한 번 급등(+15~40%) 후 서서히 감쇠,
  실제 원재료 가격의 변동성을 흉내냄.
- 세 가지로 비교: (1) 가격 피처 없음(기존 파이프라인 그대로),
  (2) 가격 피처 포함·원시 lag만(`price_lag_{1,3,5,7,10,14,21}`),
  (3) 가격 피처 포함·변화율(`price_change_pct_7d`)을 여러 시차로 미리
  계산해서 추가.
- holdout 84일, `run_baseline_candidate_backtest()`로 동일 조건 비교.

## 결과

| 구성 | WAPE | 기준모델 대비 개선율 | 가격피처로 인한 추가개선 |
|---|---|---|---|
| 계절나이브 기준모델 | 0.0939 | - | - |
| 가격 피처 없음 | 0.0632 | 32.7% | - |
| 가격 피처(원시 lag만) | 0.0656 | 30.1% | **-3.9%p (악화)** |
| 가격 피처(변화율 다중시차) | 0.0584 | 37.7% | **+7.5%p (개선)** |

MASE도 같은 패턴: 원시 lag만 추가하면 1.067→1.109(악화), 변화율 다중시차를
추가하면 1.067→0.987(개선)로 1.0 밑으로 내려감(계절나이브보다 나음).

## 해석 — 피처 "형태"가 중요하다

**단순히 가격 원시값의 지연 피처(`price_lag_N`)를 많이 주는 것만으로는
부족하다.** `GradientBoostingRegressor`는 트리 기반 모델이라 서로 다른
시차의 원시가격 두 값을 조합해 "비율/변화율"을 근사하는 데 약하다 —
`price_lag_3`과 `price_lag_10`을 둘 다 줘도 `(price_lag_3-price_lag_10)/
price_lag_10`에 해당하는 패턴을 트리 분할만으로 잘 못 찾는다.

반면 **변화율 자체를 미리 계산해서 여러 시차로 제공**하면(실제 효과
지연을 모르는 상태에서도) 모델이 올바른 시차를 스스로 골라 쓸 수 있었다.
이건 일반적인 피처 엔지니어링 교훈과 일치한다 — 트리 기반 모델에는
비율/변화율처럼 "이미 계산된" 파생 피처를 주는 게, 원재료가 되는 raw
값을 여러 개 주고 모델이 알아서 조합하길 기대하는 것보다 훨씬 낫다.

## 지금 코드베이스에 반영한 것

1. **재현성 버그 수정**: `model_selector.py`의 `GradientBoostingRegressor`에
   `random_state=42`가 없어 실행마다 WAPE가 미세하게 달랐다(이 ablation
   테스트를 돌리다 발견). 추가해서 완전히 재현 가능하게 만들었다 — 이전의
   모든 실험(M5 리트머스 테스트 포함)도 이 영향을 받았을 수 있으나, 보고된
   방향성(개선율 순위)이 바뀔 정도의 차이는 아니었다.
2. `market_price_features.py`는 아직 변경하지 않았다 — "변화율 다중시차"
   피처는 이 ablation 테스트에서만 임시로 만든 것이고, 프로덕션 모듈에
   반영하려면 실제 KAMIS 데이터로 먼저 재검증이 필요하다(아래 "다음 단계").

## 알려진 한계

- 합성 데이터 실험이라 "가격이 실제로 수요에 영향을 주는가"는 전혀
  검증하지 않았다 — 오직 "영향을 준다면 파이프라인이 찾아낼 수 있는가"만
  확인했다.
- 탄력성(0.5)과 지연(3일)을 임의로 정했다 — 실제 식품 원재료-수요 관계의
  크기나 지연은 품목·고객사마다 다를 것이다.
- GradientBoostingRegressor 기본 하이퍼파라미터를 그대로 썼다 — 피처가
  늘어나면 과적합 위험도 커지는데 전혀 튜닝하지 않았다.

## 다음 단계 제안

1. `market_price_features.py`의 `make_market_price_features()`에
   `price_change_pct_7d`를 여러 시차로 미리 계산해주는 옵션을 추가할지
   검토 (단, 실제 KAMIS 데이터로 먼저 검증 후).
2. 실제 KAMIS 가격 데이터 + 실제 고객 파일럿 수요 데이터가 생기면, 이
   ablation과 동일한 틀로 재실행해 진짜 사업 가설("가격이 이 고객사의
   수요를 예측하는가")을 검증.
3. model_selector.py 전반에 하이퍼파라미터 튜닝(cross-validation) 도입
   검토 — 이번 테스트에서 피처가 늘어날 때 과적합 여지가 있어 보였다.
