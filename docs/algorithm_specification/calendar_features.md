# 설계문서: 외부 공공 API 기반 달력 피처 (calendar_features)

> 6.3절 보완 B7 "문서화 의무"에 따라, 병합 전 설계문서와 단위테스트를 필수로
> 작성한다. AI·최적화 선임연구원은 이 문서를 리뷰·갱신하며 실증데이터 적용
> 시 설계를 직접 검증·수정할 책임을 진다.

## 목적

3.2절 A2(모델선택·확률예측) 모듈이 입력으로 쓰는 "요일·연중주기·주말·이벤트"
피처 중 명절/공휴일 이벤트를 자동 생성하고, 선택적으로 날씨 피처를 추가한다.
4.4절 예비분석에서 추석(2025-10, 2,260팩)·설(2026-02, 1,951팩)이 수요 급증의
핵심 요인으로 확인되어 최우선 외부 데이터로 선정했다.

## 데이터 소스

| 소스 | API | 제공 범위 | 용도 |
|---|---|---|---|
| 한국천문연구원 | 특일 정보(getHoliDeInfo) | 연·월 단위, 과거~미래 모두 조회 가능 | 명절/공휴일 플래그 (학습·운영 전 구간 사용 가능) |
| 기상청 | 단기예보(getVilageFcst, VilageFcstInfoService_2.0) | 발표시각 기준 약 2~3일 뒤까지만 | 발주 시점 임박 피처 (학습 데이터 전체를 채우지 못함 — 선택 피처) |

두 API 모두 공공데이터포털(data.go.kr)에서 발급받은 서비스키
(`DATA_GO_KR_SERVICE_KEY` 환경변수)를 공용으로 사용한다.

## 설계 결정

1. **공휴일은 필수, 날씨는 선택.** 특일정보는 과거 전체 구간에 소급 적용
   가능해 학습 데이터에 결측 없이 채울 수 있다. 반면 단기예보는 미래 2~3일만
   제공하므로, 과거 학습 구간에는 날씨 컬럼이 항상 NaN이다. `make_calendar_lag_features`는
   `holiday_calendar`/`weather_forecast` 인자를 `None`으로 둬도 동작해야 하며,
   날씨 컬럼이 전부 NaN인 경우 모델이 해당 피처를 사실상 무시하도록 결측
   허용 모델(GradientBoostingRegressor는 결측 미지원이므로 현재는 `dropna()`로
   학습 행에서 제외 — 아래 "알려진 한계" 참고)을 전제로 한다.
2. **격자좌표(nx, ny)는 고객별로 교체 필요.** `WeatherClient` 기본값은 서울
   (60, 127)이며, 실증고객의 생산/물류 거점 좌표로 교체해야 한다. 기상청
   격자 변환표(위경도→격자) 적용은 후속 작업.
3. **재시도·캐싱.** 두 클라이언트 모두 지수 백오프 재시도(최대 3회)를
   포함한다. 디스크 캐싱(요청 쿼터 보호)은 아직 미구현 — 운영 전환 시
   AI 선임이 필요성을 판단해 추가해야 한다.
4. **Bias 보정 포함 백테스트는 단순화 버전.** `model_selector.run_baseline_candidate_backtest`는
   4.2/4.5절 로직을 1회 홀드아웃으로 재현한 것이며, 3.5절이 요구하는 롤링
   오리진 반복 검증이 아니다. PoC 판정(7.2절)에 사용하기 전 AI 선임이
   롤링 오리진 버전으로 재설계해야 한다.

## 알려진 한계 (TODO)

- `GradientBoostingRegressor`는 결측치를 지원하지 않아 `dropna()`로 처리 중.
  지연 피처의 warm-up 구간(앞쪽 최대 28일)과 날씨 미제공 구간이 학습에서
  제외된다. 결측 허용 모델(예: HistGradientBoostingRegressor)로 교체하거나
  결측 대체 전략을 세우는 것을 고려.
- `run_baseline_candidate_backtest`의 Bias 보정계수 산출 시, 모델이 이미
  해당 구간을 학습에 포함한 상태에서 예측하므로 완전한 out-of-sample이
  아니다(계획서 4.5절 자체도 동일한 단순화를 사용함). 롤링 오리진 설계에서
  재검토 필요.
- 날씨 API의 nx/ny 위경도 변환 유틸리티 미구현.
- 디스크 캐싱 미구현 (data.go.kr 트래픽 쿼터 보호 목적).
