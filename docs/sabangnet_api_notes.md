# 사방넷 API 조사 노트

이 문서는 데이터 수집 파이프라인을 설계하기 전에 확인한 사방넷 API 관련 정보와,
실제 구현 전에 반드시 채워야 하는 미확인 항목을 정리한다.

> 이 세션의 네트워크 정책상 `sabangnet.co.kr`, `sbfulfillment.co.kr` 도메인에는
> 직접 접속이 차단되어 있어 공식 문서 원문을 확인하지 못했다. 아래 내용은
> 검색 스니펫으로 확인한 공개 정보이며, **실제 API 키 발급 후 받는 PDF/웹 문서를
> 기준으로 재검증이 필요하다.**

## 1. 사방넷에는 API가 두 종류 존재

| 구분 | 사방넷 "부가서비스 API" (레거시) | 사방넷 풀필먼트(SB Fulfillment) API |
|---|---|---|
| 대상 | 쇼핑몰 통합관리(주문 수집/송장) | 클라우드 WMS (재고/입출고) |
| 프로토콜 | 과거부터 XML 기반으로 알려짐 (확인 필요) | REST + JSON |
| 인증 | 연동키(`company_id` + `auth_key`) | API Access Key + Secret Key → signature 생성 |
| 발급 경로 | 사방넷 마이페이지 > 서비스 관리 > 연동키 관리 (유료 부가서비스 가입 필요) | 풀필먼트 API 서비스 가입 후 발급 |
| 테스트 환경 | 불명 | Sandbox 제공 |
| 주요 기능 | 결제완료/배송준비 주문 수집, 송장 등록 | 입출고, 재고 현황 등 WMS 데이터 |

우리 서비스(판매예측 대시보드)에 필요한 데이터는 **주문/판매 이력 + 재고 현황**이므로,
고객사가 어느 쪽을 쓰는지에 따라 연동 대상이 달라진다. 실무에서는 다음 순서로 확인한다.

1. 고객사가 사방넷 "쇼핑몰 통합관리"만 쓰는지, 풀필먼트(WMS)까지 쓰는지 확인
2. 각 서비스의 API 부가서비스 가입 여부 확인 (미가입 시 고객사가 먼저 가입해야 함)
3. 발급된 키 종류(연동키 vs access/secret key)에 맞는 클라이언트 구현

## 2. 확인된 사실

- 오픈API로 가져올 수 있는 핵심 데이터: **결제완료·배송준비 상태의 신규 주문**
  (판매량 예측에 필요한 시계열 기반 데이터로 사용 가능)
- 풀필먼트 API는 REST/JSON, `Access Key + Secret Key`로 signature를 만들어 인증
- 연동키/API키는 사방넷 마이페이지에서 발급 (계정 소유자, 즉 **고객사만** 발급 가능 — 우리가 고객사
  로그인 비밀번호를 직접 알 필요가 없다는 뜻이므로 온보딩 플로우 설계에 중요)
- Sandbox 환경이 있으므로 실서비스 연동 전 통합 테스트 가능

## 3. 미확인 — 반드시 실제 문서/고객사 확인 후 채울 항목

- [ ] 정확한 엔드포인트 목록 (주문 조회, 재고 조회, 상품 조회, 페이징 방식)
- [ ] Signature 생성 알고리즘 (HMAC-SHA256 추정, 타임스탬프 포함 여부, 인코딩 방식)
- [ ] 응답 페이로드 스키마 (필드명, 날짜 포맷, 상태값 enum)
- [ ] Rate limit / 호출 주기 제한 (풀링 주기 설계에 직결)
- [ ] Webhook/실시간 푸시 지원 여부 (없다면 폴링 전제로 설계 — 현재 이 전제로 설계함)
- [ ] 레거시 XML API의 정확한 request/response 포맷
- [ ] 페이지네이션/증분 조회(예: 마지막 수집 시각 이후 변경분만) 지원 여부
