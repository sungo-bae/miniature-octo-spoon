# 수집 시작 전 실버잡 사이트 자료 (2026-09-08 ~ 2026-11-03)

매일 수집(2026-10-27~)을 시작하기 전부터 silverjob.kr이 홈페이지에 쓰던 자료를,
사이트 저장소(`miniature-octo-spoon`의 `main` 브랜치) git 기록에서 꺼내 정리한 1회성 보관본입니다.
2026-11-03에 만들었습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `site_work24_syncs.csv.gz` | 사이트가 고용24 공고를 받아 저장한 112번의 기록. `commit`(사이트 저장소 커밋), `synced_at`(받은 시각, UTC), `committed_at`, `job_count` |
| `site_work24_presence.csv.gz` | 저장 기록(`commit`)마다 들어 있던 공고 `id`(고용24 구인인증번호) |
| `site_work24_postings.csv.gz` | 한 번이라도 들어 있던 공고 37,400건의 내용(마지막으로 본 값) + `first_synced_at`, `last_synced_at` |
| `site_daily_stats.csv.gz` | 2026-10-02 ~ 11-03 일별 공고 수 요약(사이트 권역 8개·직종 6개·사회공헌 세부분류) |
| `welfare_services.csv.gz` | 복지 서비스 정보 134건 (2026-10-26 기준, 사이트 복지정보 페이지 자료) |

열 이름은 사이트가 쓰던 이름 그대로입니다(`region`=사이트 권역, `job`=사이트 직종, `pay`=급여 문구, `deadline`=마감일 문구 등).

## 꼭 알아야 할 한계

- **전체 공고가 아니라 표본입니다.** 사이트의 Netlify 함수가 실행 시간 제한(약 15초) 안에 받은 만큼만 저장했습니다.
  그래서 저장 기록마다 건수가 다르고(9월 말 60~100건, 10월 초 수백 건, 10월 중순 이후 5~6천 건),
  어떤 공고가 한 기록에 없다고 해서 마감된 것은 아닙니다.
- 받은 조건: 고용24 Open API, 고령자 우대 공고 중 사이트 6개 직종에 들어가는 공고.
- 같은 `synced_at`인데 내용이 다른 기록이 있습니다(사이트 코드 수정으로 파일만 다시 저장된 경우). 기록은 `commit`으로 구분하세요.
- 2026-09-08 기록은 사이트 개편 때 만든 빈 파일(0건)입니다.
- 2026-10-27 이후 분석에는 정식 수집 자료(`data-YYYY-MM` 보관본)를 쓰고, 이 자료는 그 전 기간의 **보조 자료**(직종·지역 구성, 급여 문구, 게시 패턴 비교 등)로 쓰는 것이 안전합니다.
- 사이트에 들어온 후기·공고 접수 원본은 이름 등 개인정보가 있어 넣지 않았습니다.
